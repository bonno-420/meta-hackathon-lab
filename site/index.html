Loopwright

A development platform that turns failures in AI-assisted production into quality controls for the next run — shown here running a production workflow for fictional job postings, the test workload rather than the product.

Recorded playback — not a live run Fictional data only A verification pass permits an in-demo preview only — never publication

This page replays a recorded run and its audit trail. The workflow pins the source posting, extracts and cross-checks FACTs, waits for human approval, generates the page copy, and then re-verifies the result independently. When the source contradicts itself, it stops instead of generating.

1. Pin the source→ 2. Extract & check FACTs→ 3. Human approval→ 4. Generate copy→ 5. Independent re-verification

Run E02 stopped at the cross-check. Approval, generation, re-verification, and preview were not executed. Reason recorded: hourly pay — the FACT is ¥1,500 (source line L03: “給与は時給1,500円。”), while the summary states ¥1,700. What you are reading is the stop record, not a generated artifact.

An audit changed the output

Unstated items are now JSON null, every run

In loop 2, the extractor represented unstated items inconsistently across runs — sometimes the string “未記載” (“not stated”), sometimes an empty string. The audit flagged this. In the improvement experiment (extraction prompt v1.1), both the instructions and the schema example were made explicit: the value of an unstated item is JSON null. The two unstated items in this posting (renewal, housing) came out as null consistently, and v1.1 has been the standard extraction prompt since. Detail: experiments/exp-002-fact-extract-prompt-v1.1.md in the repository.
