## 背景と仮説

- ループ2の観察事項: 未記載項目の `value` にモデルが文字列「未記載」を入れた（想定は null）
- ループ6の作業1（v1 の再実行）で、再実行では空文字列が入り、**v1 では未記載の表現が実行ごとに揺れる**ことを実測した
- 仮説: プロンプトで「未記載項目の value は JSON の null」と指示文とスキーマ例の両方に明示すれば、表現が null に統一され、他の項目と判定には影響しない

## 変更要因（1つだけ）

- 未記載項目の value の表現規定。追加したのは指示文1文と、スキーマ例の value の型注記（string or null）のみ
- 変えていないもの: モデル（`muse-spark-1.3-contributor`）、temperature（0）、入力（FICT-J01 v1）、キー一覧、normalized の規定、実行条件（同時1件・再試行0）

- E01「一致（人間承認待ち）」、E02「停止（矛盾あり）」で v1 と同一。判定への悪影響なし
- スキーマ完全性チェック合格（15件そろい）

- 実測: 所要 44,524ms、入力 388・出力 5,504 トークン、算出コスト $0.0011396（区分: 実験）
- 機械比較の全結果は `loops/loop-006/comparison.json`
