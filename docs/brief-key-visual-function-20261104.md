# ブリーフ: 1枚画をパイプラインの機能として仕上げる（2026-11-04、統括→設計ライン）

## 目的

1枚画（LPの完成イメージ）を、パイプラインが求人票と企画から自動で作れるように修正する。統括や人間の手作業を工程に混ぜない。手作業で作った物が混ざると、パイプラインの出力かどうか分からなくなるため。

## 現状（実測、2026-11-04時点）

- 組成と描画の機能はある: `src/page-layout.mjs`（企画の構造からレイアウト組成）、`src/render-page-image.mjs`（完成ページを1枚の画像に描画）。commit `08280a5`、pipeline-fix テスト 77/77、全スイート通過
- ただし run7/run8 の実走は統括のドライバ経由で、CLI 単体では再現できない。未着地の控え（画像の設計 imageDesign の組成反映）が統括の作業ツリーにある
- 伝える設計（だれに・何を・どう伝えるか）は企画入力にあるが、完成イメージの構成には効いていない。写真とカードの骨格だけで、訴求の割り当てがない

## 修正の内容

1. **伝える設計の実装**: 企画の対象・訴求（appeals）を完成イメージの構成に効かせる。ページの各ブロックが「どの訴求・どの事実を担うか」の対応表（message map）をパイプラインが生成し、レイアウト記録と提示記録に残す。訴求に割り当てのないブロックを置かず、根拠のない要素を置かない
2. **画像の設計の確定**: 企画の imageSpecs の design（purpose / aspect / fit）を正規の入力として検証し、組成がそれに従う。統括の作業ツリーの控えの使用可否は設計ラインが判断する
3. **実行の再現性**: FICT-J02 の実走が `node src/run-demo.mjs` の CLI だけで再現できること。ドライバ、手書きのプランファイル、手作業の後処理を使わない。不足する CLI 配線は足す
4. **検証**: CLI から FICT-J02 を1枚画チェックポイントまで実走し、完成イメージ・レイアウト記録・対応表が提示できること。対応するテストを追加し、全スイート通過
