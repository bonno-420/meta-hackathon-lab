# D10 デザイン方針と拡張の進め方

- 日付: 2026-10-28
- 決定者: 本人（判断ゲート1）
- 根拠資料: docs/design/design-system-and-ultraflame-integration-review.md（調査・推奨）、docs/design/design-system-review-audit.md（Wonder 独立監査、総合判定は「修正」。指摘は改訂で反映済み）

## 決定

1. プレビューの CSS は手書き継続＋CSS 変数化とする。Bootstrap は導入しない。
   - 当初（同日）は Bootstrap（CDN参照、バージョン固定）で決めたが、デザインシステム調査・監査・再検討を経て差し替えた。
   - 理由: 設計仕様（トークン）を CSS 変数で実装する流れとの適合、提出範囲では現行の手書きで足りること、本人が Bootstrap にこだわらないこと。
   - 必要になれば、レビューの再評価条件に沿って戻ることができる。
2. UltraFlame との関係は「統合」ではなく「機能の取り込み」とする。UltraFlame を使うのでも、部品を作って統合するのでもなく、UltraFlame の中から必要な機能を本プロジェクト側に実装する（拡張部分）。
   - 形は「仕様・考え方を参照し、実装は期間内に新規に書く」に限る。コードの直接移植は、提出物の「期間中の新規作成」要件との関係で新規性リスクがあるため行わない。第三者コードの取り込みも行わない。
3. 取り込みの中心は「設計仕様＋適合監査のペア」とする。第一弾は、設計仕様形式の実装（トークンの原簿）、適合監査（コントラストチェック＋訴求設計との人間確認）のゲート候補化。
4. スケジュール方針: 本体（既存の開発）は止めず、常時提出可能な状態を保つ。拡張は工程の前倒しで生じる余力で開発し、提出への組み入れは組み入れ判断ゲート（11/01）で、完成し監査を経たものだけとする。

## 影響

- 依存関係の追加はなし。プレビューの実装方式は現行のまま（設計仕様と変数化は 10/31 の枠当てで実施）。
- docs/design/appeal-design-draft-v0.md §8 のデザイン行を本決定に合わせて訂正した。
