# D9: Muse Bot 主体の開発運用

- 決定日: 2026-10-27（監理ラインの独立監査で「修正」→ 統括が修正を適用 → 再監査で「合格」。本人が受け入れたため有効）
- 提案者: 統括（Muse）
- 起点: 本人の指示「Muse Bot 主体の開発運用への整合・調整」（2026-10-27）と、前提の確認（「Muse Bot」は統括（Muse）自身を指すことを本人が確認、2026-10-27）
- 調査記録: `docs/design/muse-bot-alignment-survey.md`（矛盾 K1–K7、未確認 U1–U3）

## 決定内容

1. **開発の主体は Muse Bot（統括）とする。** Muse Bot は自らの環境（GitHub 接続、実行環境、ブラウザ）を用いて、調査・設計・実装・記録の一連の工程を、最初から完成まで自ら進める。別の AI が完成済みの設計を用意し、Muse Bot が単に実装する形にはしない
2. **人間（本人）は判断と承認に専念する。** コミット、課金が発生する API 呼び出し、外部への送信・公開は、従来どおり本人の明示承認がある場合のみ行う（D8 は存続する）
3. **独立監査は監理ライン（Muse Wonder）が担う。** Muse Bot は自らの成果物に最終の合格を出さない。受け入れの判定は、監理ラインの監査を材料として、本人が統括と共同で行う。監査の判定区分（合格 / 修正 / 前段階への差し戻し）と停止条件は、basic-design v1.1 と AGENTS.md の規定を存続する
4. **ラインと Wonder / Spark の位置づけ。** 監理ラインは独立監査の担い手として存続する。設計・制作の実施は原則として Muse Bot が行う。Wonder / Spark は、(a) 独立監査、(b) Muse Bot が文脈や専門性の理由で切り出す専門パス、として使う。製品（L2）の実行時モデルは Spark 1.3 系のみであり、本項の用途には含めない（決定内容 6 のとおり変更しない）
5. **Codex / OpenCode はフォールバックとする。** Muse Bot の環境で実行できない作業（例: 本人の PC のローカルでしか確認できない事項）に限り使い、使った場合は理由を台帳（`docs/model-selection.md`）に残す
6. **製品（L2）の実行時モデルは変更しない。** Spark 1.3 系のままとする。本決定は開発運用（L1）の主体に関するものであり、D4 のうち本決定と矛盾する部分（駆動環境と役割分担）に限り本決定が優先し、それ以外の D4 の内容は存続する

## 前提条件と制約（実測に基づく）

- Muse Bot の GitHub 読み書きは接続済みである。書き込みは本人の承認カードを経るため、D8 の「明示承認時のみ」と整合する
- Meta Model API のキーは本人の Windows の環境変数（`MODEL_API_KEY`）にあり、Muse Bot の実行環境にはない。Muse Bot が実 API 実行（製品の FACT 抽出など）を行うには、キーの安全な提供方法（Secure Vault 経由など）を別途定める必要がある。それが定まるまでの間、実 API 実行を要する作業は従来のライン環境（本人の PC 側）で代替し、その旨を台帳に記録する
- Muse Bot は本人の PC のローカルフォルダに直接アクセスできない。コードと記録の受け渡しは、従来どおり GitHub を正本とする

## D4 の条項との対応（監査 M3 への対応）

D4 は書き換えず、本決定が受け入れられた場合の条項単位の読み方をここに明示する。

| D4 の条項 | 本決定での扱い |
|---|---|
| 駆動環境（Codex（主）/ OpenCode） | 上書きする。駆動主体は Muse Bot とし、Codex / OpenCode はフォールバックになる |
| 実装・制作の主力は Spark 1.3 Contributor（L1） | 部分存続。L1 の既定の実施は Muse Bot が行い、Spark は専門パスで使う |
| 設計の起点は Wonder | 上書きする。起点は Muse Bot とし、Wonder は独立監査と専門パスを担う |
| サブ（Spark）が実施と一次確認、Wonder が監査と判断 | 部分存続。実施と一次確認は Muse Bot、監査は監理ライン（Wonder）という対応になる |
| Wonder は作業統括、Spark は作業員（ライン別体制） | 部分存続。監理ラインの独立監査は存続する。設計・制作の作業統括は Muse Bot が担う |

| モデルの単価・仕様などの事実 | 存続する |
| ライン名の訂正（「管理」を「監理」とする） | 存続する |

D5 への影響: 予算区分の上限額は据え置く。「設計・監査」区分の説明（旧役割に依存する記述）と Muse Bot 自体の推論費の帰属は、本決定の発効時に D5 への追記で定める。

## 前提条件への補足（監査の観察事項への対応）

- 本決定の「前提条件と制約」に書いた Muse Bot の機能範囲は、調査記録 `docs/design/muse-bot-alignment-survey.md` の U2（統括の実測記録）に基づく。独立した実行ログ等の証跡は、今後の Muse Bot のパスで記録として残す
- 「Secure Vault 経由など」は、利用可能性が未確認の候補例であり、利用できることを前提にしない
- Muse Bot の GitHub 書き込みの単位をここに定義する。書き込みは GitHub API 経由でファイル単位に行い、各書き込みが main へのコミットとなる。本人の承認カードは、その書き込み（1ファイルの作成・更新）単位の承認であり、これをもって D8 の「コミットは本人の明示承認時のみ」の運用単位とする
