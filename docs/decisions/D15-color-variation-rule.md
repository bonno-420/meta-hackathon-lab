# D15 — 色のルール: 前回と同じ型が続く場合は前回と異なる配色にする

日付: 2026-11-04
決定者: 原田徳一（本人）
経緯: FICT-J03 の完成 LP（loop-026 run3）を見た本人が「色合い同じじゃない？」と指摘。実績を確認すると、E02・J03 run1・J03 run3 がすべて型 P-WORK の同一配色（緑）で、続けて同じ見た目のサイトができていた。本人は「『していなければ前回と色合い変える』って話をしなかったか」と確認したが、記録（メモリ・日次ログ・設計文書）を当たった範囲では、その形の合意は残っていなかった。残っていたのは本人の制作原則「デザインの差別化は色とロゴと写真で担うのが基本」（2026-11-04）であり、実装は型ごとに色を固定したままで原則を満たしていなかった。そのうえで本人が「『前回と同じなら色合いを変える』をルールとして記録して実装する」と決定した。

## ルール

- 差別化は型のパターン・色・ロゴ・写真で担う（既存の原則）。
- **前回の制作と同じ型が続く場合は、配色を前回と異なるものにする。** 型が変われば配色も変わる。
- 「前回」は制作履歴（loops/design-history.json、ツール自身の記録）の直近の制作を指す。再開した実行は自分自身の記録を前回として数えない。

## 実装

- 各型に配色バリエーションを3種持たせ（従来の配色が第1バリエーション）、導出（src/lp-design.mjs）が前回の型と配色を受け取り、同型が続く場合は次のバリエーションを選ぶ。選択と理由は lp-design.json に paletteId と variedFromPrevious として記録される。
- ランナーは制作のたびに履歴へ追記する（同じ実行の再開では重複させない）。
- 配色の値そのものは従来どおり市場のリサーチ裏付けのない候補であり、その旨は記録に明記したままにする。本ルールは「繰り返しを避ける」ためのもので、値の根拠を主張するものではない。
