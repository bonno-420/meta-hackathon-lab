# D14 — ゲート昇格（G-A / G-B / G-C）と給与表記の決定

日付: 2026-11-04
決定者: 原田徳一（本人）
経緯: loop-026 の知見集約で統括が提示したゲート昇格候補 G-A〜G-C について、本人が「ゲートGは全部昇格で」と決定。あわせて loop-026 の介入記録 I-1（月給が FACT スキーマに残らない）への決定として、給与表記の規則を定めた。

## 決定1: ゲート昇格（3件すべて）

- **G-A**: 募集要項の完全性を完成チェック **C7** に昇格（決定的検査）。募集要項の表に、全 stated 事実の値と、行だけが持つ必須項目（仕事内容・休日・応募資格）が入っていることを機械で確認する。企画経路（planning あり）の完成判定に適用する。
- **G-B**: 見出しの機械スキャンを pagecheck（**src-pagecheck-v3**）に追加。見出し（タイトルブロックの文）が条件だけの文（雇用形態・契約期間など）である場合と、長さの目安（日本語50字・英語120字）を超える場合に落とす。判断レビューの見出し基準と併存する決定的な床である。
- **G-C**: 画像設計チェック（G7）の拡張。生成前確認の記録（coverageChecks: ヒーローで説明できていない部分と、必ず画像にする福利厚生・待遇）が設計にない場合は落とす。

いずれも学習フロー規定（候補→検証→承認→制作経路への組み込み）の承認を経た昇格であり、本決定をもって恒常化した。

## 決定2: 給与表記（I-1 への回答）

- 給与は原本が記載する形で記載する。月給制なら月給、時給・日給・年俸ならその額を記載する。
- 時給・日給・年俸の場合は、あわせて**現実的な月収例**を表記し、「ひと月のおおよその総支給が分かるように」する。月収例は記載された材料（時給×実働×想定日数、日給×想定日数、年俸÷12）からのみ計算し、想定日数が記載されていない場合は作らない。
- 月収例には、**残業・夜勤・手当などは考慮していない旨を注記**する。

### スキーマへの反映

- FACT スキーマに給与キー **monthlySalary（月給）・salaryDaily（日給）・salaryAnnual（年俸）** を追加（全18キー）。抽出プロンプト fact-extract-v1.2 で「給与は記載された形で記録する」「月給は monthlyIncomeGuarantee（保証の明記がある場合のみ）ではなく monthlySalary に記録する」と定義した。
- 背景の実測: FICT-J03（月給制）では、キー不在のため抽出が実行ごとに monthlyIncomeGuarantee と未記載の間で揺れた（3回実測）。v1.2 の抽出では monthlySalary が安定して stated になった。
- 旧い事実集合との互換: キーが片側に無く、もう片側で未記載の場合は「情報なし」として等しいとみなす（compareFactSets）。stated の出現・消失は従来どおり差分として止まる。
