## 骨格の不変の確認

- 全体の流れ（収集 → 構造化と型化 → 目録 → 提案と承認 → 生成 → 適合監査＋散文評価）と、本体との接続2か所（生成への型セット追加、適合監査の後ろへの散文評価の追加）は初版から変わっていない。
- 未決事項の枠組み（決める人と目安を付けた表）は維持され、追加は U8（G1 の規則の確定）と「実施ブリーフで決める事項」の小節である。どちらも初回監査が求めた追加であり、枠組みの変更には当たらない。
- 冒頭に改訂履歴が置かれ、対応の範囲（G1〜G5、所見2・所見3）が追える形になっている。

## 新規の不整合の有無

- §2・§3 の追記と §4 以降の参照に、新たな矛盾は見つからなかった。確認した参照は次のとおり。§4 の提案と承認は目録 ID と版で参照セットを固定し、§3 のレコード項目（ID、版、状態）と合う。§5 は生成後に §2 の「生成後の条件」を確認するとし、§2 側に同名の条件が実在する。§6 の「型に沿っているか」は承認された型セットを前提とし、§4 の承認とつながる。
- 型のライセンス状態（最も弱い状態に合わせる案）と、最小実装で「ライセンス状態は登録可に限定する」ことは矛盾しない。最小実装の事例は架空で手作りのため全件が登録可であり、最も弱い状態でも登録可になる。

## 観察事項（残存指摘ではない。実施段階への申し送り）

- O1: 型のレコードの「ライセンス要約」は 1 件の要約の形のままで、由来事例が複数ある場合に要約をどう書くか（列挙か、最も弱い事例の要約か）は定められていない。判定には影響しない。実施ブリーフで、要約は由来事例の列に対応づける形に固定するとよい。
- O2: U8 が確定するまでの間、型の状態はレコードの「状態」と由来事例の状態の両方を見る必要がある。実施の記録様式では、型の状態と由来事例の状態を並べて残す欄にすると、確定後の移行が楽になる。

- 実測: 改訂版と初回監査レポートの実文を照合し、追記の有無と箇所、節間の参照の一致を確認した。
