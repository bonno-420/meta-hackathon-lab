# LP フルパイプライン化 設計 v1（投稿入力だけで完成 LP までを 1 回の実行にする）

- 作成: 2026-11-03（設計ライン）
- 状態: 設計。監査（監理ライン）→ 実装 → 監査 → 受け入れ（本人と統括）の順で進める。本書は実装を含まない
- 依頼: `docs/lp-full-pipeline-fix-brief-20261103.md`（統括、本人の判断）
- 対象: `src/run-demo.mjs` の統合実行に、画像生成と LP 組み立てを工程として接続する。loop-015/016 の実験側の道具立ては本体へ持ち込まず、本体側で最小に実装する

## 現状の継ぎ目（設計の出発点）

- 統合実行（runDemo）は 抽出 → 照合 → 承認（再確認）→ 文章生成 → 再検証 → プレビュー を持ち、工程は注入（deps）で差し替え可能になっている。文章だけで「終わった」ことになりうるのが継ぎ目である。
- 画像生成と LP の組み立ては loop-015/016 の実験側にあり、本体の工程と完了の定義の外にある。
- 既存の振る舞い（抽出、照合、承認、矛盾での停止）には触れない。E02 は従来どおり照合で止まり、後段は実行されない。

## 工程の接続（決定）

統合実行の工程を次に拡張する。文章生成の後に画像生成と LP 組み立てを入れ、再検証はその後に置く。

```
抽出 → 照合 → FACT比較（候補と固定 FACT）→ 承認 → 文章生成 → 画像生成 → LP組み立て → 再検証（完成の判定を含む）→ プレビュー（任意）
```

（工程列の明記、M3: FACT 比較は既存の統合実行にある段であり、今回の拡張でも不変条件の対象に含める。順序と振る舞いは現行どおりとする。）

- **画像生成（新工程）**: モデルは `muse-image-1.0`。画像には文字と数字を焼き込まない。作る画像は LP の設計に沿った hero 1 点と節ごとの画像とし、節の数は生成文の構成から決める（節の画像の要否と数は、生成の記録を入力として決める。推測で増やさない）。実行は既存工程と同じく注入（deps）で差し替え可能にし、ライブの CLI が実 API の実行を担う。失敗（生成できない、ファイルが残らない）した場合は止めて記録する。
- **LP 組み立て（新工程）**: 生成文（承認済み FACT 由来の文）と画像を組み合わせ、完成した LP のページ（HTML）を組み立てる。文は生成の記録の文をそのまま使い、編集しない。画像の参照は組み立て時点で実在するファイルだけを指す。組み立ては API を呼ばない。
- **プレビューの扱い**: 既存のプレビュー（デモ表示）は完成した LP とは別物として残す。今回の完了の判定は LP の組み立てまでとし、プレビューの生成は従来どおり任意とする。

## 完成の定義と再検証（決定）

再検証は、従来の機械検査（入力同一性、根拠検査の再実行）に加えて、完成の定義への照合を持つ。完成は次の 4 点がすべてそろうこととする。

| # | 完成の条件 | 確かめ方 |
|---|---|---|
| C1 | 文章がある | 生成の記録に文が存在し、組み立てたページに全文がそのまま入っている（ページ側の文の欠けは C1 で判定する。M1） |
| C2 | 画像がある | 画像生成の記録にある画像がすべて実在し、ページから参照されている |
| C3 | ページが組み上がっている | LP のページのファイルが存在し、文と画像の両方を含むこと（存在と両含有の確認に留める。具体的な文の欠けの判定は C1 が担う。M1） |
| C4 | 根拠検査が pass | 既存の根拠検査の再実行が pass である（従来どおり） |

- 1 つでも欠けたら「未完成」として止め、記録する。欠けたものの生成を成功として扱わない（欠落は矛盾と同じく止める条件として扱う、というブリーフの原則に従う）。
- 完成の照合は、再検証の記録の中に機械検査の結果として残す。人間の意味確認の扱いは従来と変えない（確認が未完了の間は合格にしない。人間の確認の対象は文章であり、画像の意味の確認は今回の範囲に含めない）。
- 既存の `verify.mjs` の判定の意味は変えない。完成の照合は統合実行側の工程として足し、再検証の記録に含める形とする（道具の分割は実装時に決める）。
- 完成照合の置き場所の制約（M2）: 照合のコードは統合実行側（`run-demo.mjs` 側）に置き、`verify.mjs` は改変しない。記録への組み込みは、統合実行の記録の `stages.verification` を拡張して行い、完成照合の結果をその中に含める。
- 完成の記録への明記（N3）: 完成の記録には「画像の意味は範囲外である」旨を明記する。人間の確認と完成の判定は文章と機械的な含有を対象とし、画像が内容として適切かは今回の判定に含めない前提を、記録の読み手に分かる形で残す。

## 費用の記録

- 画像の費用は 1 枚あたり $0.01 の算出値として、実行ごとの記録に残す（枚数と算出の根拠を併記する）。確定実費は Billing 突合による扱いは従来どおりであり、算出値を確定値として扱わない。
- 文章側の費用の記録は従来どおりとする。合計の出し方も従来の統合実行の形を維持し、画像の区分を足す。

## テストの条件

既存のテストスイートが全部通ることを前提に、次を足す。

| # | 条件 | 期待 |
|---|---|---|
| T1 | 文章はあるが画像の生成が失敗する（注入で失敗を再現） | 未完成で止まり、完成として記録されない |
| T2 | 画像の記録はあるが実ファイルが欠けている | C2 で未完成になる |
| T3 | 組み立てたページに生成文の一部が欠けている | C1 で未完成になる（C3 はファイルの存在と文・画像の両含有までとし、文の欠けの判定は C1 に一本化する。M1） |
| T4 | 正常系（文章・画像・ページ・根拠検査がそろう） | 完成と記録され、後段へ進める |
| T5 | E02 の停止系 | 従来どおり照合で止まり、画像生成以降は実行されない |
| T6 | 画像の費用の記録 | 枚数 × $0.01 の算出値が記録に残る |

## 範囲外と不変条件

- 抽出、照合、FACT 比較（候補と固定 FACT）、承認、矛盾での停止の振る舞いは変えない（M3）。架空データのみを扱う。
- loop-015/016 の実験（型、ペルソナ、Baseten 系列）は本体へ混ぜない。本設計の画像と組み立ては本体側の最小実装であり、実験側の成果物の転用ではない。
- 変更は最小で戻せる形にする。工程の追加は注入の形を踏襲し、既存工程の差し替えで無効化できるようにする。

## 実装への申し送り

- 実装順序は 画像生成 → 組み立て → 完成の照合 の順とし、各段で対応するテストを足す。
- 完了の定義: 投稿入力（FICT-J01）だけから 1 回の実行で、画像つきの完成 LP が得られ、その実行が動画の実画面テイクとして記録できること（ブリーフの Done）。
- 判断と変更理由、検証結果は loop 記録として Git に残す。
