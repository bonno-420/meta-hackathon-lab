## 総合判定: 修正（前段階への差し戻しは不要）

- 設計の骨格は設計指示に沿っている。設計対象（収集／構造化と型化／目録／提案と承認／生成／散文評価）は過不足なく設計され、指示を優先した6点の食い違い処理はいずれも妥当である。本人の確定事項（流通量の仮説、指定取得のみ、ライセンスの保留遷移、型の在庫化、デザイン側の対象外）も、後述の明記不足を除いて反映されている。本体との接続も2か所に絞られ、在庫側が未完成でも本体の提出可能性に影響しない形である。
- ただし、型の出所とライセンスの帰属の決め方（複数収集物から抽象化した型に、単一レコードの出所とライセンス状態をどう付けるか）が設計されておらず（指摘 G1）、コピーの線引きの照合が原文の保持を前提とする点と未決事項 U2（本文を残すか）との連関が記録されていない（G2）。いずれも設計の段階で追記できるものであり、骨格と前提を覆すものではないため、差し戻しとはしない。
- 未決事項リスト自体は、決める人と目安が付いており概ね完全である。未決であること自体は不備として扱っていない。

## 観点ごとの照合

### 指示との一致（設計対象の過不足、6点の食い違い処理）

判定: 一致している

- 設計対象は指示の6節すべてに対応する。収集は指定取得元のみ・密度による分岐・バッチ記録（指示 §1）、構造化と型化は抽出項目と既存の厳格 JSON 抽出との対応・分類軸・抽象化手順・候補→検証→承認→登録（§2）、目録は1レコードの項目（指示の最低限をすべて含む）と単位の定義と保留の状態遷移（§3）、提案と承認は手順と記録フォーマットと還流（§4）、生成は3層＋型セットの位置づけ（§5）、散文評価は別層の設計と観点の育て方と記録フォーマット（§6）が、それぞれ設計されている。過剰な対象の追加はない（デザイン素材の制作順序などは対象外として切られている）。
- 食い違い処理の6点は妥当である。起点を収集に置くこと（ドラフト §1、目録でライセンスを扱う）、流通量への改名と仮説の明記、デザイン側を対象外とし共通化だけを検討事項に含めること、保留を目録の外に置くことで「確認が通ったものだけが目録に載る」と両立させること、密度の分岐を主とし前提資料の優先観点を多い側の信号に取り込むこと、クロールを後付けの拡張点とすること。いずれも指示の文面と矛盾せず、処理の理由も追える。

### 本人の確定事項との一致

判定: 概ね一致している（明記の不足は指摘 G3）

- 出現回数は「流通量」と名付けられ、「効果の証拠ではない」という仮説が引用の形で明記され、承認の根拠にせず並び替えと賞味期限にだけ使うことが書かれている（ドラフト §2）。指示と構想の確定事項どおりである。
- 収集はユーザーが指定した取得元のみで、無差別収集を含まず、自動クロールは後付けの拡張点に留まっている（ドラフト §1）。密度が高い側の「競合広告を検索する」手順も、指定取得元の範囲内の検索として読む限り矛盾しない。検索の対象自体も指定に含まれることは、実施の段階で明示されるとよい。
- ライセンスの申告と確認が食い違った場合は自動で登録も却下もせず保留に回り、最終判断が本人に上がり、判断と理由がレコードに残る遷移になっている（ドラフト §3）。保留中は提案の対象にしないことも明記されている。
- 文章は型を在庫化し、完成文は在庫化しない前提は、構造としては保たれている（目録の主対象は型であり、生成文は目録の登録対象に含まれていない）。文体のルールとは別の棚であることも明記されている（ドラフト §2）。ただし「完成文を在庫化しない」こと自体の明文がないため、指摘 G3 とする。
- デザイン側は在庫・インデックスの汎用ストックとして対象外であり、文章側と混ざっていない。目録スキーマの共通化は検討事項と未決（U5）に留まっており、非対称は保たれている。共通項目が「デザイン素材にもそのまま使える形」とされている点は、指示が求めた検討の範囲内である。

### 本体との接続

判定: 満たす

- 接続点は「生成への型セット追加」と「適合監査の後ろへの散文評価の追加」の2か所に絞られ、いずれも提案として明示されている。型セットは事実を上書きしない追加の入力と位置づけられ、生成プロンプトの版を上げて実験として記録すること、型ありの結果は既存経路の合格実績を引き継がないことが書かれている。散文評価は再検証の判定（プレビュー許可まで）には触れない。
- 収集から型化までは本体の実行経路に入らず、在庫側が未完成でも本体の提出可能性（工程1〜6、`loops/` の記録前提）に影響しない。提案と承認の記録と散文評価の記録は `loops/loop-NNN/` に置く形で、本体の記録の前提に乗っている。収集バッチ記録の置き場所は本体と分ける提案で、未決（U4）として残されているため、最小実装の着手前に決める必要がある。

### コピーの線引き

判定: 形は満たすが、原文保持との連関が未記録（指摘 G2）

- 判定はモデルのコンプライアンス任せにせず、登録時（型に収集物の言い回しの連続や固有名・数値・固有の比喩が残っていないこと、文字列の重なりの機械検出）と、生成後（特徴的な言い回しの連続で一致しないこと、構成の一致だけではコピーとみなさないこと、数値は原本由来かどうかで判定すること）の2時点で確かめる形になっている。しきい値は未決事項 U1 として、決める人と目安つきで明示されており、未決であること自体は不備ではない。
- ただし、登録時と生成後のどちらの照合も、収集物の原文が保持されていることを前提とする。未決事項 U2（実在の広告の本文を記録に残すか、型だけを残すか）を「型だけを残す」と決めた場合、この照合は設計ごと成立しなくなる。その連関がドラフトに記録されていない（G2）。

### 最小実装の規模

判定: 規模は妥当。実施の手順の確定は実施ブリーフ側の宿題として指摘する（G5）

- 「架空の型3–5件を手で登録し、E01 で1周」（目録の最小形、提案と承認、型あり生成1回、散文評価1回）は、組み入れ判断ゲート（11/01）までに作って回す範囲として妥当である。収集の自動化、流通量の集計基盤、大量登録を期間外とした切り分けも正しい。対象は架空データだけで回る形であり、実在の広告は使わない。
- 成立の判定（1〜4が架空データだけで1周し、記録が `loops/` に残ること）と、間に合わない場合は拡張として切り離して本体のみで提出する扱いも、D10 の方針と整合する。
- 一方で、着手に必要な実施の確定（型セットを生成の道具へ渡す形、新しいプロンプト版の付け方、散文評価の実施者とモデル、架空の事例の作り手、監査パスをゲート前にどう組み込むか）はドラフトに書かれておらず、未決事項にも上がっていない。これらは設計の欠落というより実施ブリーフで決める事項だが、ゲートまでの残り日数を考えると、宿題として明示すべきである（G5）。

### 未決事項の完全性

判定: 概ね完全（所見は下記）

- U1〜U7 はいずれも、決める人（本人を中心に、材料の提示者が併記されている）と決める目安（「〜の前」「〜の時点」）が付いており、抜けの大きい項目はない。実在広告の本文の扱い（U2）は論点として立っている。
- 所見1（U2）: G2 のとおり、U2 の判断材料には「登録時・生成後の照合が原文を必要とすること」を含めるべきである。「型だけを残す」場合の代替の照合方法（例: 照合用に原文を目録とは別の場所へ期限つきで保持する）も、判断の選択肢として提示されるとよい。
- 所見2（U1）: しきい値の判断材料（重なりの長さ、一致箇所の数）を記録する形式を先に決めるという提案は妥当である。架空の事例で最小実装を回す段階からその形式で記録すれば、ゲート時点の判断材料が実績として揃う。
- 所見3（U4）: 収集バッチ記録の置き場所は、最小実装の成立判定（記録が `loops/` に残ること）との関係で、着手前に「バッチ記録だけは収集側に分ける」のか「最小実装の間は loops に含める」のかを決める必要がある。
- 所見4（追加候補）: 散文評価の実施者とモデル、型セットの入力の形は、実施ブリーフで決める事項として未決リストへの追加を検討すること（G5 と同じ）。
