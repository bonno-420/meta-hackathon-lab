### A1【高】Bootstrap 暫定決定の出所と着地状態の事実誤認

- 根拠: 初稿は「現 HEAD の `docs/` 内に Bootstrap への言及はなく（grep で 0 件）、Git 上の記録としては未着地」「統括との会話で暫定決定」と繰り返す（初稿:33,72,155）。しかし初稿自身が調査 HEAD とする `74b6516` のコミットで追加された `docs/design/appeal-design-draft-v0.md:67` に、「デザイン（プレビューの枠）は Bootstrap（CDN参照、バージョン固定）を採用する。シナリオ固定（10/31）で枠の文章が固まってから、文章と合わせて1回で当てる（2026-10-28 本人決定）」と明記されている。監査側の grep でも、`docs/` 内の Bootstrap への言及はこのドラフトに実在する（初稿自体を除く）。
- 正確な状態は「未着地」ではなく、「訴求設計ドラフト v0（下書き、ゲート対象ではない）に本人決定として着地済みだが、`docs/decisions/` の決定記録にはなっていない」である。
- 影響: 推奨2は「会話だけの暫定決定の配置方法を見直す」という前提で書かれているが、実際には本人がドラフトに明記した決定（採用＋配置方法＋当てる時期まで含む）への見直し提案であり、重みが違う。また §9 の判断ゲート1の設計（決定をこれから着地させる）もずれる。
- 修正案: 初稿 §1.1 と §7 の記述を訂正し、出所を `appeal-design-draft-v0.md` §8 と明記する。判断ゲート1は「新規決定の着地」ではなく、「ドラフトに記載された本人決定（Bootstrap・CDN・版固定）を維持するか、採用自体または配置方法を見直すか」の再確認として再定義する。あわせて、初稿の調査時点（開始 HEAD と終了 HEAD の区別）を記録し直すこと（初稿の内容は着地前の状態と整合する部分があり、どの時点で何を読んだかが追えない）。

### A2【中】推奨2の論法: 版固定 CDN を無固定 CDN として論じ、SRI を評価していない（監査側の独立判断を含む）

- 根拠: 暫定決定の文面は「CDN参照、バージョン固定」である（`appeal-design-draft-v0.md:67`）。これに対し初稿の推奨2は、「CDN は実行のたびに変わりうる外部変数を入れる」「無固定 CDN を明示的に否定する UltraFlame の作法」を根拠に、CDN 参照の不採用と版固定ローカル配置への見直しを提案する（初稿:119-120,168）。監査側で実文を確認したところ、UltraFlame の作法文書が否定するのは `cdn.tailwindcss.com`（無固定の Tailwind Play CDN）への置き換えであり、対象も製品も異なる（`skills/hyperframes-core/references/tailwind.md`）。また本リポジトリ自身、デプロイでは `npx --yes wrangler` という無固定の外部取得を受け入れている（`loops/loop-010/run-record.md:121`）。再現性の厳格さの適用が、対象によって一貫していない。
- 欠けている評価: 版固定 CDN と SRI（integrity 属性による配信バイトの検証）の組み合わせが検討されていない。版固定＋SRI では、取得される CSS はハッシュで検証されるか、検証に失敗すれば読み込まれない。初稿の再現性の根拠（同一バイト列と sha256 の文化）は、生成物と入力ファイルに対するものであり、公開ページが外部 CSS を参照することと同列には扱えない。UltraFlame の作法も、動画レンダリングの決定性という文脈のものであり、公開プレビューの閲覧文脈への無条件の転用には留保が要る。
- **監査側の独立判断**: 無固定 CDN を避け、使うなら版を固定するという原則は妥当である。しかし暫定決定は既に版固定であり、**版固定 CDN＋SRI で、公開プレビューの用途には十分**だと判断する。ローカル配置が優れるのは、オフライン表示（デモ動画の撮影時にローカルで開く場合を含む）、同一オリジンで完結すること、第三者へのリクエストを出さないことに限られ、必須の条件ではない。したがって、配置方法だけを今の時点で決定として覆す技術的根拠はない。検討の順序は「Bootstrap 自体が枠に必要か（現行 CSS は5ルールで、プレビューは表1つが中心であり、限界便益は小さいという初稿自身の指摘がここに効く）→ 必要な場合のみ配置方法」であるべきだ。
- 修正案: 推奨2を改訂し、(i) 暫定決定が版固定であることを正しく引用する、(ii) 選択肢を「手書き継続／版固定 CDN＋SRI／版固定ローカル配置」の3つとし、それぞれの利害（可用性、オフライン、第三者依存、運用の手間）を対等に提示する、(iii) ローカル配置の優位の主張は上記の範囲に限定する。そのうえで判断ゲート1で本人が選ぶ形にする。

### A4【中】統合方式1（形式・原則の共有）の新規性・ライセンス・第二正本のコストの見落とし

- 根拠: 初稿は方式1を「結合ゼロで即日可能。公開/非公開の境界を侵さない」とし、トークンの語彙・設計仕様の形式・色とコントラストの原則を「共有する」とする（初稿:78,85-88）。しかし次の3点が評価されていない。(i) 新規性: 本プロジェクトの提出物はビルド期間中（2026-10-26〜11-04）に新規作成したもののみが対象であり、期間外の既存物の流用はリスクになる（`docs/design/context-pack-v1.md` §2、基本設計の停止条件の新規性リスク）。UltraFlame 側の資産は2026-10-14以前から存在するため、具体的なパレット値・プリセットの文面・部品を持ち込むことは、形式の借用ではなく既存資産の転用になりうる。(ii) ライセンス: UltraFlame 側には所有者の proprietary と第三者由来（designer-skills の MIT 表示保持、HyperFrames の Apache-2.0 等）が混在し（`LICENSES.md`）、公開リポジトリ（MIT で公開予定）への転記には表示義務と切り分けが要る。両リポジトリの権利者が同一であることは自作部分の緩和要因だが、第三者由来部分は別である。(iii) 第二正本: UltraFlame 側の作法は、派生コピーを「第二の編集正本」にしないことを求めており（`README.md` の snapshot の扱い）、形式をコピーして hackathon 側で育てることは、その作法と緊張する。
- 修正案: 方式1の「共有する」を、抽象的な原則と語彙の「参照」に限定し、具体的な値・文面・部品の転用はしないことを明記する。転用が必要になった場合は、対象を特定し、新規性（Official Rules の精読結果を含む）と表示義務を確認したうえで本人が判断する、という条件を付す。

## 推奨2（Bootstrap の配置方法）に対する監査側の独立判断

依頼に応じて、推奨2だけを独立に判断する。

- **妥当な部分**: 無固定の CDN 参照（版も検証手段もない参照）を避けること、使うなら版を固定すること、現行ページの規模ではフレームワークの限界便益が小さいという見立ては妥当である。
- **妥当でない部分**: 暫定決定は既に「バージョン固定」であり、無固定 CDN への反論は決定の文面に当たっていない。SRI が評価されておらず、再現性の根拠は、公開プレビューの用途では版固定＋SRI で概ね満たされる。UltraFlame の作法は Tailwind Play CDN と動画レンダリングに関するもので、そのままの転用はできない。
- **結論**: 版固定 CDN＋SRI で十分であり、ローカル配置は必須ではない（オフライン表示や同一オリジンを求める場合の強化策）。したがって推奨2は、「配置方法の見直しを決定として提案する」形から、「Bootstrap を使うかどうか自体を含め、3つの選択肢を判断ゲートで本人が選ぶ」形に改めるべきである。現時点で配置方法だけを覆す材料はない。

## その他の推奨への監査側の評価

- 推奨1（統合方式1の採用、2・3の不採用、4の保留）: 方式2・3を採らない理由（消費者が2つしかいないこと、公開と非公開の同居ができないこと）は、初稿の根拠の範囲で支持する。方式1は A4 の条件を付したうえで支持する。方式4の保留も妥当である。
- 推奨4（デモ動画を UltraFlame に全面依存しない）: 期限（11/04）と、対象ブランチ時点でリリース HOLD・Windows のみ検証という状態からは、フォールバックを残す判断として支持する。ただし根拠は A3 のとおり2026-10-14時点の状態に限定される。
- 推奨5（管理画面の選定保留）: 対象が未定義の段階で選定しないことは、選択肢を狭めない扱いとして妥当である。

## 実測・記録・判断の区別

- **実測（本セッションで確認した事実）**: 提出された ZIP と展開した初稿のバイト数と sha256 が、依頼の記載と一致した。meta-hackathon-lab 側の現行コード、訴求設計ドラフト、台帳、決定記録、実行記録を実文で照合し、Bootstrap への言及がドラフトに実在すること、テストファイルが5件であることを確認した。UltraFlame は対象ブランチを一時クローンして全木（680件）を検索し、初稿の §1.2 の主要な事実（Bootstrap の不使用、Tailwind の実使用なし、プリセット13種・パレット9種、HOLD、ライセンス、フォント、作法文書の文面）が当該ブランチで成立することを確認した。リモートに多数の他ブランチが存在し、対象が2026-10-14のスナップショットであることも確認した。
- **記録に基づく事項**: 本人の Bootstrap 決定の経緯（会話を含む）、UltraFlame の他ブランチの現在の状態、動画制作の実績は、記録と初稿の記述に基づく。本監査では他ブランチの中身は走査していない。
- **判断（監査としての判定）**: 総合判定「修正」、推奨2への独立判断（版固定 CDN＋SRI で十分）、指摘 A1–A9 の重大度の付け方は、本監査の判断である。推測で埋めた箇所はない。
- **未確認事項**: UltraFlame の対象ブランチ以外の現在の状態（LP アダプタの実装状況を含む）は未確認である。GSAP のライセンスの現行版の条件は、対象ブランチの記録の範囲で確認したもので、最新の配布条件の確認はしていない。動画制作に UltraFlame を使う場合の可用性は、本監査では実証していない。
