## 工程案

### 工程1: 抽出・照合の仕上げ（10/28–29）

- プロンプト v1.1 の改善実験: 未記載項目の value の扱いを明示する（1要因変更、exp-001 の流儀で記録）
- 再現性検証: 同一条件での再実行とばらつきの確認
- 抽出結果のスキーマ完全性チェック（キーの欠落検出）を追加する。ゲート候補として記録する

### 工程2: 承認工程の実装（10/29–30）

- 承認の記録: 誰が、いつ、どの原本版と FACT 版に対して承認したかを残す
- 矛盾がある場合は承認できない分岐にする（「警告を無視する承認」を作らない、G-INV-3）
- 原本または FACT が変わったら、既存の承認を無効と判定する

### 工程3: 生成工程の実装（10/29–30）

- 承認済みの FACT だけから LP 文章を生成する（モデルは Spark 1.3 系）
- 未承認の状態では実行できない。FACT にない情報を生成物に足さない

### 工程4: 再検証の実装（10/30）

- 生成物が承認済み FACT と一致するかを照合する（機械検証できる範囲＋意味の対応は人間の確認）
- 食い違えば生成工程へ差し戻す。再検証の合格の効果は「デモ内プレビューの許可」まで（G-INV-4）

### 工程5: 統合実行とデモシナリオ化、公開プレビュー（10/30–31）

- 正常系（E01 の流れ）と停止系（E02 の流れ）を一続きで見せられる実行形にする。凝った UI は作らない
- 生成物の公開先として Cloudflare Pages を用意する（独立した Pages プロジェクト、pages.dev のサブドメイン、リポジトリの `site/` を公開。MJ のドメインや DNS には触らない）
- 置くもの: E01 で生成された LP プレビュー、E02 で停止した状態の表示、プロジェクト説明と GitHub の記録へのリンク
- Pages のセットアップ自体は前倒しで行い、実物の生成物への差し替えは本工程で行う

### 工程6: 提出の形に整える（10/31–11/02）

- 各実行の記録が `loops/` に残ることを確認する
- README で L1 と L2 の関係、再現手順、記録の場所を説明する
- デモ動画（11/01）と最終監査・提出（11/02）は `docs/roadmap-v1.md` のとおり
