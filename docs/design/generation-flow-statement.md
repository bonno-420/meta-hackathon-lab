# Generation flow statement

- Drafted: 2026-11-03 (design line, Step 0b). Confirmed by the user

## How generation actually flows

A posting goes in as text. The tool pins it as the source, extracts the facts with a Meta model — each fact tied to a source line, and anything unstated left unstated — then cross-checks the facts against the source. A human approves that exact fact set; the approval expires if the source or the facts change. Before production starts, the checkpoints are settled with the user in one go: the full four-point set (planning, the key visual, the text, and the assembled page) or the light two-point set (the key visual and the assembled page), and that choice is asked up front, not piecemeal during the run. Production then runs in this order: planning first (who it is for, and what it should say), then a single overall key visual that fixes the look, then the page copy written from the approved facts alone, then the real images generated to that specification, and finally the page assembled. The result is re-verified independently — every sentence traced back to its source lines, and the page checked for completeness — and a contradiction at any point stops the run instead of being smoothed over. Where the tool finds a defect it can fix itself, it retries a few times; anything still unfixed is recorded as a hold and the run continues to preview, with the holds presented together with the preview rather than hidden. The preview is always shown to the user, text included — it is never a stage that finishes unseen. Whoever runs it, the same input takes the same path and leaves the same kind of record.
