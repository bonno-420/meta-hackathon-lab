## 観点1: ブリーフとの一致（変更要因は1点か、他は同一条件か）

判定: 一致している

- 手順0（ターゲット設定とペルソナ設計）は新設として実施され、求人票だけを材料に、対象層の軸を経験の有無ではなく期間・収入・時間の見比べに置き直し、ペルソナ P-01（悩みと希望 W1〜W5 と、事実の範囲内の訴求と表現の限界）と話し手 S-01（求人の担当者という当事者の立場、ファネルの入口としての位置づけ）が設計されている（`loops/loop-013/persona-design.md`）。ペルソナの悩みや希望は読み手側の事情として書かれ、原本にない求人の条件は作られていない。話し手も声と立場の定義に留まり、会社や担当者についての事実は作られていない。
- 変更要因の同一性の確認: 対象の組（原本 v1、固定済み FACT v1、承認 FICT-J01-approval-1）は loop-012 と同一である。型4件（LIB-PAT-001〜004 v1）の内容と版は作り直されておらず、目録の構成と枠の文面が loop-012 の使用時と一致することを、両ループの使用プロンプトと目録で照合した。評価観点も初期候補4件のまま同一である（観点5）。
- 同一でない部分は2つあるが、いずれも実施ブリーフの範囲内の差分である。第一に参照セットの選択が 001＋002＋004 から 002＋003＋004 に変わった。これは手順1が明示的に許容した変更であり（「変わってもよい。変える場合は理由を記録する」）、ペルソナの軸の置き直しと生活翻訳の材料の有無を理由として提案に記録されている。第二に、未記載項目の締めの扱いが「条件の要約」から「質問への誘いとして表現してよい」に変わった。これは手順0の企画承認における本人の修正そのものであり、変更要因（企画を前に置くこと）の内側の変更である。したがって、変更要因は企画の1点に絞られていると判断する。
- 生成プロンプトは新しい版 `lp-generate-v3-persona` で、`lp-generate-v2-typed` とも型なし経路とも区別されている。生成は1回だけである。

## 観点4: 生成と照合の妥当性

判定: 妥当（「ご相談ください。」の扱いを含む）

- 再検証の機械検査は、入力同一性 pass、根拠検査の再実行 pass（6文、issues なし）、機械検査 pass であり、最終判定は人間の確認が未完了のため未確定のままである。生成物は本体のプレビューには使われていない（`loops/loop-013/persona-verification-result.json`）。
- 生成文の数値はすべて固定済み FACT v1 由来である。コピー照合の数値由来チェック（1,500円、10,000円、20日、3か月、60分、8時間）に加え、時刻（09:00〜18:00）も根拠検査で FACT の値と照合されている（`loops/loop-013/copy-check-after-generation.json:42-67`）。
- 生成後コピー照合の扱いは記録として妥当である。機械照合では由来事例のうち LIB-CASE-004 との間で8文字以上の共通部分が1件（「ご相談ください。」）あり、これを「市場の定型の締めの表現」として人間側で扱ったことが、コピー照合と散文評価の両方に明記されている。この判断は、第一に当該の文言が本人の承認時の修正で明示的に許容された形そのものであること、第二に8文字という短い定型の締めであり、事例に固有の場面や言い回しの一致ではないことから、支持できる。なお「市場の定型」という根拠は市場データによる裏づけではなく、本人の承認時の扱いと表現の一般性によるものである点は、記録の読み方として留意する（指摘ではない）。他の事例との一致はなく、登録時の照合（型に事例の文が残っていないこと）も loop-012 で確認済みである。
- 生成テストは監査側でも再実行し、39/39 pass と、コミットされていない検証記録（`loops/loop-013/check-verification.json`）との一致（`runAt` を除く）を確認した。テストはスタブ経由で、実 API は呼ばれていない。

## 観点5: 散文評価と比較の妥当性

判定: 妥当

- 評価は loop-012 と同じ初期観点4件で、実施者は制作ラインの Wonder、観点の昇格は行われていない。評価はプレビューの可否を決めていない（最終判定は未確定のままであり、評価の差し戻しも実験に対するものとして区別されている）。
- 判定の変化には、生成文の引用に対応する根拠がある。当事者の声は「要修正」から「良い」へ（話し手を担当者に置いたことと、締めの言葉が付いたことを根拠とし、声が文末と締めに留まることも併記されている）、型への適合は「要修正」から「良い」へ（loop-012 の文の重複と詰め込みが解消したこと）、生活翻訳は「要修正」のままだが時間帯の翻訳が入って根拠は強くなったこと、第三者視点の混入は「良い」のままであることが、両ループの生成文を引いて並記されている（`loops/loop-013/prose-evaluation.md:16-34`）。物差し（観点と判定の段階）は loop-012 と同じであり、比較の条件はそろっている。
- 評価の前提として、参照セットの構成が変わったことは比較の条件の差として明示されている（同:6）。セットの変更は企画変更の帰結であるため、この比較は「企画＋それに伴うセット選択」の効果を見るものとして読むのが正確であり、記録もそのように書かれている。

## 観点6: 組み入れ判断への材料

判定: 読み取れる（薄い点は指摘 L2）

- 変更要因と効果は記録から読み取れる。企画を前に置くことの1点に対し、生成文の差分（話し手の声の向き、重複の解消、未記載の扱いの変化）と、評価の判定の変化（当事者の声と型への適合の改善、生活翻訳の残り）が、生成物と評価の両方に残っている。
- 残る課題も残っている。生活翻訳が生活の場面まで届いていないこと（差し戻しあり）、型の検証で翻訳の範囲を先に決める論点、コピーのしきい値（U1）が未決のままであること。
- 実費は記録され、監査側で再計算して一致した。生成1回で $0.0015838（D4 単価による算出値、入力 2,440・出力 6,699 トークン）であり、手順0と評価には API の実行がない。確定実費は Billing 突合待ちである。
- 試算注記の必須語（「月収は保証しない」）と表現の柔らかさの両立問題は、材料として残っている。生成文では、変動の述べ方（勤務日数や残業の増減などで変動する）と試算の仮定を置いたうえで「月収は保証しないことをお伝えします」と閉じており、loop-012 で残された両立の形がそのまま現れている。あわせて、FACT にない要素（残業）を変動要因に使う表現も、loop-012 の留意点を引き継ぐ形で生成文に現れている（指摘 L2）。

## 実測・記録・判断の区別

- **実測（本セッションで確認した事実）**: 実施ブリーフ、loop-013 と loop-012 の記録一式、目録、新規コードを実文で照合した。生成テストをリポジトリ外の出力先で再実行し、39/39 pass と検証記録との一致を確認した（実 API は呼んでいない）。生成1回の費用を単価から再計算し、記録値と一致した。作業ツリーに追跡済みファイルへの変更がなく、追加が新規ファイルと目録の更新だけであることを確認した。生成文の数値がすべて固定済み FACT v1 にあること、型4件の文面が loop-012 の使用時と変わっていないことを、両ループのプロンプトと目録で照合した。
- **記録に基づく事項**: 手順0と手順1の承認（判断者・日付・修正内容）、生成が1回だけであること、その usage は、実施側の記録に基づく。承認の時刻は記録されておらず、順序は記録と生成内容の整合で確認した。
- **判断（監査としての判定）**: 総合判定「合格」、参照セットの変更と未記載の締めの扱いの変更を変更要因の内側とみなすこと、「ご相談ください。」を市場の定型として扱う判断を支持すること、指摘 L1〜L3 を重大度「低」とすることは、本監査の判断である。推測で埋めた箇所はない。
- **未確認事項**: 承認の前後関係を時刻で独立に証明する証跡はない（上記のとおり）。確定実費は Billing 突合までは未確認である。
