# 対応表: 監査論点 S1–S12 と実装工程確定版 v1

- 作成: 2026-10-27（設計ライン）
- 起点: `docs/design/implementation-steps-review.md`（監査、判定「修正」。論点 S1–S12 と「修正の完了条件」6項目）
- 反映先: `docs/design/implementation-steps-v1.md`（確定版。再監査 `docs/design/implementation-steps-rereview.md` で合格）
- 位置づけ: 再監査の観察事項 O1（対応表そのものがリポジトリ内にない）への対応として、設計ラインの対応表をここに置く。再監査側が実文から再構成した照合と突き合わせるための資料とする

| 論点 | 指摘の要旨 | 反映先 | 反映内容 |
|---|---|---|---|
| S1 | 提出フォームの事前準備がない | 工程6「提出文面の準備」 | Cerebral Valley 提出フォームの入力項目を事前に確認し、説明文、トラック（Indie、D2）、URL の置き場所、使用ツールの説明の下書きを用意する。正式項目が未確認の間は下書きを確定文として扱わない |
| S2 | 生成文ごとの根拠保持がない | 工程3、工程4 | 工程3で生成文ごとに FACT 項目と行 ID を付けて保持し、行 ID を持たない文は含めない。工程4で数値・単位・範囲・否定・条件付き表現を行 ID で再照合する |
| S3 | FACT 版の固定と承認の操作形態が未定義 | 工程1（承認対象の固定）、工程2 | 採用した FACT を版つきで固定し（原本版と組で特定）、工程2の無効判定は版の一致で行う。承認は記録への記入による最小操作とし、記録形式は工程3が依存するため 10/29 の早い時点で先に固定する |
| S4 | ライセンス・帰属の表記がない | 工程6「ライセンスと帰属」 | LICENSE と帰属表記の配置作業を工程に含める。どのライセンスにするかは本人の判断事項として未決と明示する |
| S5 | 動画台本との接続が弱い | 工程5「統合実行とシナリオ」 | シナリオの記録を、11/01 のデモ動画の台本の下書きにそのまま使える形（場面の順序、見せる記録と成果物）で残す |
| S6 | 範囲外の明記がない | 「対象外」の節 | E03–E10 の評価拡張は対象外とし、統合デモの完成と提出を優先する旨を明示する。ペルソナ実施も本書では決めない |
| S7 | 再現性検証の位置づけが v1.1 §8 とずれる | 工程1（順序の分離） | 「v1 の同一条件での再現性（根拠: ループ2監査の観察事項）→ プロンプト v1.1 の 1 要因の改善実験」の順に分け、対象版と根拠を明記する。混同しない旨は共通の決まりにも置く |
| S8 | 生成と統合・公開の見積もりが甘い | 工程3（最小形）、工程2 | 工程3は E01 のみ、文を FACT の項目に対応させる最小形を先に固定する。工程2の承認形式を早期に固定し、工程4の前倒しに備える |
| S9 | 記録の必須項目が末尾でしか確認されない | 「全工程に共通する決まり」の記録、各工程の完了条件 | 各工程の完了条件に、その工程の記録（入力版、成果物、判定、実費または未記録の理由）を `loops/` に残すことを埋め込む。工程6は全体の欠落チェックに役割を変更する |
| S10 | Pages の承認 checkpoint がない | 工程5「公開プレビュー」の承認 | プロジェクト作成とデプロイの前に本人の明示承認を得て、承認まではセットアップしない。前倒しは承認が得られ次第とする |
| S11 | 公開物の表示と公開前チェックが弱い | 工程5「公開前チェック」 | 架空であることの明示、実データ・秘密情報・未確定の主張の混入なし、公開承認と読める表現なし、を確認して記録に残し、1つでも欠ければ公開しない。規約詳細は未確認と明記する |
| S12 | 転んだ場合の切り離し条件がない | 工程5の位置づけ、「リスクと切り離し」 | 公開プレビューは必須物ではなく遅れれば切り離す。縮小順序（公開プレビュー → ペルソナ → E03以降）を明示し、工程1–4 と工程6 は落とさない。工程3が安定しない場合の代替（FACT の表形式表示）も置く |

監査の「修正の完了条件」6項目との対応: 条件1 は S1–S4、条件2 は S7、条件3 は工程5の M2 切り分け（工程1–4 と一続きの実行までを M2 とし、公開は 10/31）、条件4 は S9、条件5 は S10・S11、条件6 は S12 で満たす。詳細は再監査レポートの照合を参照する。
