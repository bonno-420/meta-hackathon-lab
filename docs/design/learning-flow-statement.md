# Learning flow statement

- Drafted: 2026-11-03 (design line, Step 0b). Confirmed by the user

## How the findings accumulate

Nothing the system finds is allowed to quietly become a rule. When an audit flags something, or a run shows a pattern, it is first written down as a finding with its evidence. A change is tried as a single-factor experiment and measured; the finding and the fix are recorded next to each other in a learnings ledger. Most fixes end there — an audit judges them, and that closes the matter. A human's approval is reserved for the few heavier steps: promoting or withdrawing a standing gate, and making or changing a recorded decision. Only what passes that bar becomes a permanent rule — so the same failure cannot return unnoticed, and the platform never improves itself in secret. Every improvement can be traced back to the run that produced it, the audit that judged it, and, where the bar required it, the person who accepted it.
