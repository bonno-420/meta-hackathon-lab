## 観点2: 根拠検査の再実行の設計（同じ物差しを使う是非）

判定: 設計は妥当である。独立性はブリーフ §3 の定める3点で担保されている

- 道具は新しい物差しを作らず、`src/generate.mjs` の `checkGrounding` と `src/approve.mjs` の `checkApprovalValidity`・`sha256File` を import して再利用している（`src/verify.mjs:18-19`、`src/generate.mjs:139-217`）。これはブリーフ §2「道具は既存の検査を import して再利用し、新しい物差しを作らない」の定めどおりである。
- 独立性の担保は物差しを変えることではなく、監査側でも次の3点を確認した。(i) **申告値を材料にしない**: `src/verify.mjs` は工程3の実行記録（`generation-run.json`）を一切読まず、生成物の `status` フィールドも参照しない（生成物自体に status フィールドは存在しない。結果の `target` に転記される promptVersion・model は生成物ヘッダのメタ情報であり、判定には使われていない）。(ii) **同一性を現在のバイトから取り直す**: 観点1のとおり。(iii) **再実行する**: grounding は同一性を確認したファイルの組（生成物・FACT・原本の実ファイル）に対して再検証側の実行として走り、結果は工程3の申告値とは独立に `verification-result.json` の `grounding` に記録されている。監査側が CLI を再実行したところ、入力同一性と grounding の結果はコミット済み記録と完全に一致した（人間確認なしのため最終判定は `pending-human-confirmation` となるのが正しい挙動である）。
- 物差しを共有する残余の限界は明記しておく。`checkGrounding` 自体に盲点がある場合、その盲点は生成時と再検証時で共通になる（共通モード）。現在の機械検査の範囲は工程3監査の観察事項1のとおり限定されており（円金額と時刻の逐語、代表的な数値項目の値の保持、未記載の断定、仮定と非保証の文言）、期間・個数などの数量表現と意味の対応は人間の確認が担う分担である。したがって「同じ物差し」は、生成の合格をそのまま追認する構造にはなっておらず、盲点の最終的な受け皿は作業4の人間確認に置かれている。この設計は、物差しを分けることで生じる「生成と再検証で基準がずれる」問題を避ける代わりに共通モードを受け入れる選択であり、ブリーフ §3 が監査に問うた是非としては、現行の分担（機械の範囲の限定＋人間確認の必須化）のもとでは妥当と判断する（指摘3）。

- 文ごとの記録は対象7文すべてにあり、各文について生成物の本文・factKeys・sourceLines と一致すること、結果がすべて「対応あり」で、detail に項目対応・未記載項目への言及なし・公開/申込表現の混入なし（文1では契約期間3か月の数量の一致、文3では否定の保持、文5では仮定の保持と月収提示なし）が書かれていることを、監査側で生成物と機械的に対照して確認した（7文すべて本文・factKeys・sourceLines が生成物と完全一致）。

- 記録の作られ方の留意点として、`verification-result.json` の `verifiedAt`（2026-10-27T23:21:31Z = 2026-10-28 08:21 JST）は機械検査の実行時刻であり、人間確認（09:11 JST）より前である。最終判定 pass の行は、機械実行の出力に人間確認を記入して確定させた複合の記録であり（run-record 追記:109 が変更範囲を明示している）、CLI には完了した人間確認を入力して最終判定だけを再導出する経路がない。監査側では、コミット済みの人間確認セクションを `runVerification` に注入する関数レベルの再実行で、最終判定 pass が再導出でき、コミット済み verdict と一致することを確認した。したがって判定の導出自体は再現できるが、再現経路が CLI ではなく関数注入である点と、`verifiedAt` が最終確定の時刻ではない点は、指摘2として残す。

## 観点4: 判定が生成物の status や工程3の申告値に依存していないこと

判定: 依存していない

- `decideVerdict` の入力は `inputIdentity`、`grounding`、`humanConfirmation` の3点のみであり（`src/verify.mjs:183`）、生成物の status、promptVersion、model、工程3の `generation-run.json` の値は一切参照しない。合格は3点すべてが満たされた場合に限られ、効果は「デモ内プレビューの許可までであり、公開の許可ではない（G-INV-4）」と結果と run-record の両方に明記されている（同:234-241、`loops/loop-009/verification-result.json:278-285`）。
