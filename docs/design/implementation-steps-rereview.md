## M2 の切り分けの照合

照合対象の文言:

- roadmap: 10/30 は「統合デモの全工程が通る状態にする」（`roadmap-v1.md:16`）、10/31 は「デモシナリオの固定。README と提出文面の下書き。Official Rules 精読」（同:17）、M2（10/30）は「統合デモの全工程（抽出 → 照合 → 承認 → 生成 → 再検証）が通る」（同:27）。
- 確定版: 統合実行とシナリオは 10/30 の作業として正常系（E01）と停止系（E02）を一続きで見せられる実行形にし、シナリオの記録は動画台本の下書きに使える形で残す（v1:59-62）。その上で「M2 の判定対象はここまでとする。すなわち、工程1–4 と一続きの実行形が通り、記録が残っていることを M2 の達成とする。次項の公開プレビューは M2 に含めない（10/31 の作業とする）」（v1:64）とし、roadmap 自体の改訂は行わない旨を添えている。

判断:

1. **公開プレビューの除外に矛盾はない。** roadmap の M2 定義（roadmap:27）は抽出から再検証までの5工程の列挙であり、Pages を含んでいない。確定版が公開部分を M2 の外（10/31）に置くことは、この定義と衝突しない。
2. **「一続きの実行形」は roadmap への追加の解釈だが、矛盾ではない。** roadmap:16 の「全工程が通る状態」を、工程1–4 が個別に通るだけでなく一続きの実行形として通ることと読む確定版の定義（v1:64）は、前回監査が工程案側での切り分けとして提示した文言（review:47）に基づく。roadmap の日程（10/30 に通す、10/31 は別作業）をずらすものではない。
3. **シナリオの「固定」の時期は動いていない。** roadmap:17 の「デモシナリオの固定」は 10/31 である。確定版が 10/30 に作るのは「シナリオの記録」であり、位置づけは動画台本の「下書き」に使える形（v1:62）にとどまる。記録（下書き）の作成が 10/30、固定が 10/31 という読み分けが可能であり、確定版は「固定」を 10/30 とは主張していない。M2 の判定時にシナリオ記録を達成の証拠に含めるかどうかは v1:64 の「すなわち」以下の列挙（工程1–4＋一続きの実行形＋記録）で判断し、固定そのものは 10/31 の作業として扱うのが、両文書を通した読み方である（観察事項 O2）。
