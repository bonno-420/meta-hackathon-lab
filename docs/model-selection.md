## 現在の方針

- 駆動環境: Codex（主）/ OpenCode。できる限り Meta のプロダクトを優先する
- **作業統括 = Muse Wonder**: 統括（Muse）から受けた依頼をもとに、作業の分解、作業員への文脈の供給、指示、成果の取りまとめと一次品質管理を行う。原則として自分では実装しない。差し戻しが重なる場合は、修正回数とコストの見合いで直接実施に切り替える
- **作業員 = Muse Spark 1.3 Contributor**: Wonder の指示と文脈を受けて、実装・調査・ドラフト・分類・記録整形などの実作業を行う
- **受け入れ側 = 統括（Muse）と本人**: 成果物を一緒にチェックし、監査判定と記録（決定記録、台帳、ロードマップ）を行う。Wonder は自ら統括した作業に最終の合格を出さない
- 製品（L2）の実行時判定: Muse Spark 1.3 系（変更なし）

- 2026-10-27: 初版（D4 決定時）。実装・制作の主力は Spark Contributor、Wonder は設計・監査の要所
