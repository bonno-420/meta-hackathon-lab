## 現在の方針

- 注記: 本方針は D9 に基づく。D9 は 2026-10-27 に監理ラインの再監査で合格し、本人が受け入れて有効となった

- **駆動主体 = Muse Bot（統括）**: 調査・設計・実装・記録の一連の工程を、自らの環境で最初から完成まで自ら進める（D9）。別の AI が用意した完成済みの設計を単に実装する形にはしない
- **人間（本人）**: 判断と承認に専念する。コミット、課金が発生する API 呼び出し、外部への送信・公開は本人の明示承認時のみ（D8）
- **独立監査 = 監理ライン（Muse Wonder）**: Muse Bot の成果物を監査する。Muse Bot は自らの成果物に最終の合格を出さず、受け入れの判定は監査を材料に本人（と統括）が行う
- **設計・制作の実施は原則として Muse Bot** が行う。Wonder / Spark は、独立監査、Muse Bot が切り出す専門パス、製品（L2）の実行時モデルとして使う。外部セッションを使う場合はラインごとに分けて開き、このリポジトリのフォルダ内で起動する
- **フォールバック = Codex / OpenCode**: Muse Bot の環境で実行できない作業に限り使い、理由を本台帳に残す
- 差し戻しが重なる場合は、同じ経路の差し戻しが2回続いたら自動で回さず、原因と選択肢を記録して本人に判断を上げる
- 製品（L2）の実行時判定: Muse Spark 1.3 系（変更なし）

- 2026-10-27: 役割分担を具体化。サブが実施＋一次確認まで、Wonder は監査・判断に専念し原則として作業しない。差し戻しが重なる場合のみ、修正回数とコストの見合いで Wonder が直接実施する（コスト感の明文化）
- 2026-10-27: 体制を具体化。Wonder を作業統括（作業の分解、文脈の供給、指示、取りまとめ、一次品質管理）とし、Spark を作業員とした。文脈の詳細な切り出しは Wonder 側で行い、統括は依頼と受け入れ条件の提示、成果物のチェックと記録に寄る。本人の作業分担の方針による
