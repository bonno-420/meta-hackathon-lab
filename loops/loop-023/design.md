# loop-023 設計: 画像工程（設計・チェック・差し戻し・監査ゲート）

2026-11-04。仕様は本人の言葉（image-step-spec-20261104.md）が正本。
対象は1枚画（完成イメージ）と、その写真の生成経路。文章工程は変えない。

## 1. 画像設計工程（新設: src/image-design.mjs）

入力は承認済み企画と FACT。出力は画像設計レコード（run ディレクトリに保存し、工程記録に残す）。
企画の imageSpec ごとに設計エントリを作る:

- **purpose**: その画像が担う訴求（basis の appeal の文）または事実（factKey の項目名）。目的のない画像は設計されず、生成もされない。**枚数はこの設計そのもの**（ヒーロー1、説明は section の spec の分だけ、場所は最大1）
- **subject**: 何を写すか。spec の description を役割別の構図規則で組み立てる。ヒーローは建物・職場そのものが主役で、車両は主役にしない。説明画像は仕事の行為そのもの
- **depiction（描き方）**: ヒーローは写実可（ページの顔、印象として読まれる）。**説明・場所の画像はイラスト調**（生成画像は実際の写真ではなく、説明の位置では記録として読まれるため、はっきりイメージ図と分かる描き方にする）
- **placement（置き場と大きさ）**: ヒーローは上部に大きく。説明・場所は対応する文章ブロックの脇に小さく（幅の4割以下）。説明画像を大きく置かない
- **mustNotImply**: 含ませてはいけない含み。常設（寮・寝室、現金・金額、特定の時刻、通勤手段や車両を主役にすること、読める文字・数字・ロゴ）＋企画の notSay 由来

## 2. チェック機能

- **設計チェック**（生成前）: 全エントリに purpose / subject / depiction / placement があること。枚数の規則（ヒーローちょうど1、場所は最大1）。説明画像の depiction がイラスト調であること
- **プロンプトチェック**（生成前）: 既存の適合チェック（notSay＋常設禁止）に、ゲート台帳の用語を加える
- **完成イメージチェック**（提示前、既存ゲートの拡張）: 対象があること、全訴求に置き場があること、全写真に設計があること、配置が設計どおり（ヒーローは大きく上部、説明は小さい差し込み）であること

## 3. 差し戻し修正工程

- 設計チェック不合格 → 生成前に止め、理由を記録する（お金を使わない）
- プロンプトチェック不合格 → その画像だけ設計から作り直して再試行する（上限つき）。差し戻しのたびに理由を記録する
- 完成イメージのゲート不合格 → 提示しない。理由とともに失敗として止まる（既存の挙動）

## 4. 監査機能: 指摘された点が次のゲートになる

ゲート台帳 `src/dicts/image-gates-v1.json`: 各ゲートに id・出所・基準・種類（設計/プロンプト/配置）を持つ。
チェック機能は台帳の全ゲートを実行し、結果（ゲートごとの合否）を工程記録に残す。
新しい指摘は、学習フロー確定文どおり候補→検証→本人の承認で台帳に昇格する。今夜の分は、本人がこの機能そのものを仕様として指示し、指摘も本人のものなので、初版ゲートとして直接入れる:

- G1 寮・寝室の含み禁止（既存の常設禁止から）
- G2 現金・金額の含意禁止（既存）
- G3 特定の時刻を示す時計の禁止（既存）
- G4 通勤手段（バス等）を主役にしない（既存の notSay 運用を常設化）
- G5 車両を主役にしない（2026-11-04 本人指摘: トラック主体だと運転・積み込みの仕事に見える）
- G6 説明画像を大きくしない・写実にしない（2026-11-04 本人）
- G7 設計のない画像を生成しない（2026-11-04 本人: 設計工程の欠落の指摘）
- G8 レイアウトは設計どおりに組む（2026-11-04 本人: レイアウトが雑すぎる）

## 5. レイアウト設計（src/page-layout.mjs）

形の参照は loop-020 の1枚画（要素の不適合は除く）:

- 薄いグレーの地に、白いページカード（角丸・影）を置く
- ヒーローはカード上部いっぱいに大きく、角丸
- タイトルは紺のカードがヒーローの下端に**重なる**
- 条件カードは2列、白・角丸・影、アイコンはオレンジ（現金・家・時計のアイコンは使わない）
- 説明画像は文章ブロックの脇に小さい角丸の差し込み（参照形の帯写真は、本人の新しい規則「説明画像を大きくしない」に従い小さくする）
- 詳細はチェックリストのカード
- CTA は紺のフッター帯にオレンジのピルボタン

## 6. 検証

実企画（FICT-J01 / FICT-J02 の承認済み企画ファイル）でテストする: 設計が作れること、
植えた違反（車両主役のプロンプト、写実の説明画像、目的のない画像）でゲートが止めること、
差し戻しが記録されること。最後に CLI のみで FICT-J02 を実走する。
