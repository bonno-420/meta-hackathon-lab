# E01 参照セット再提案 (FICT-J01) — 承認記録フォーマット (design §4)

## 企画への参照

- 対象層・ペルソナ・訴求: 承認済みの企画（`loops/loop-013/persona-design.md`、2026-10-29 に修正して承認）を使う。対象層は、短期（3か月）の有期契約の仕事を検討し、時給と勤務日数から収入の見通しを見積もりながら、契約期間の短さと先行きの分からなさも見比べる人。ペルソナは P-01「条件を見比べてから決めたい、短期勤務の検討者」（悩みと希望 W1〜W5）。話し手は S-01「求人の担当者（当事者）」で、文章は応募を集める流れ（ファネル）の入口に当たる
- 原本の版: FICT-J01 v1（`src/fict-j01-v1.json`）と固定済み FACT v1（`src/facts/FICT-J01-facts-v1.json`）、承認 FICT-J01-approval-1
- 生成の事実は原本と FACT からのみ取る。型は文章の形だけを与え、事実と数値は与えない。ペルソナの悩みや希望は読み手側の事情であり、求人の事実として生成文に足さない

## 提案内容

提案する参照セット（目録 ID と版の列）:

1. **LIB-PAT-002 v1（条件先行・試算明示型）** — ペルソナの決め方（まず期間と収入の見通しを見る）に直接対応する。時給1,500円（L03）、月20日勤務は試算用の仮定（L04）、月収は保証しない（L03）という事実の組があり、条件を先に示し、試算は仮定のままにする構成が合う。W2 への対応が中心になる
2. **LIB-PAT-003 v1（生活翻訳型）** — loop-012 では提案しなかった型を、今回は入れる。理由は2つある。第一に、承認されたペルソナが読み手の生活側の事情（昼間の時間帯で働き、夕方以降の予定を読みやすくしたい）を意図層に明示したため、翻訳の受け側が企画として与えられた。第二に、翻訳の材料になる事実（勤務時間09:00〜18:00、休憩60分、実働8時間、L04）が原本にある。翻訳はこの時間の事実を読み手の生活の言葉に移す範囲に限り、新しい条件は足さない。W3 への対応になる
3. **LIB-PAT-004 v1（未記載明示・締め型）** — W1（更新の有無）と W5（寮）に対応する。未記載を断定せずに示す構成が合う。締めの扱いは、ペルソナ承認時の修正により、未記載であることだけで閉じず、質問への誘い（「ご相談ください」で丸める形を含む）として表現してよいことになった。誘いは表現に留め、連絡先や応募方法そのものは作らない

提案しない型と、その理由:

- **LIB-PAT-001 v1（安心導入型）は今回は入れない。** loop-012 との変更点である。理由は、ペルソナの軸が経験の有無ではなく期間・収入・時間の見比べに置き直され、安心導入型の訴求（未経験への安心）が主たる対象層と合わなくなったためである。あわせて、支援や研修の事実が原本にないため、loop-012 の散文評価でも導入の役割が弱いと判定された。型の登録自体は維持し、対象層が未経験層である別の企画で使う候補として残す

loop-012 のセット（001＋002＋004）との差分は、001 を外し、003 を入れたことである。変更要因（企画を前に置くこと）の効果を比較できるように、この差分と理由をここに残す。
