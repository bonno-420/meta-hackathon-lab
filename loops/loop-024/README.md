## 問題の所在（統括の確認）

- これまでのレイアウトは固定テンプレート1本（page-layout の決め打ち構成）で、その形は統括が loop-020 で作ったモックに由来した。企画が決めていたのは「どの訴求・事実がどの枠に入るか」だけで、ページの構造そのものは企画から導かれていなかった。「企画から読み取って作った」は言い過ぎだった

## 仕組み化（src/lp-design.mjs）

- 構成パターンを候補として3つ置く: P-COND（条件先行、LIB-PAT-001 の順序）、P-WORK（仕事先行）、P-LIFE（生活適合先行）
- 導出は決定的: 企画の訴求（第一確認の事実を持つか／仕事そのものか／生活適合か）と画像指定の信号を数え、最も強い読み手関心のパターンを選ぶ。スコア・信号・理由は設計記録（lp-design.json と layout 記録）に残り、監査できる
- ページ生成（見本）と組み立て（完成LP）は同じ設計記録に従う。パレットもパターンに紐づくトークンとして記録される（市場の裏付けはない候補のまま、と記録に明記）
- ゲート追加: 設計の導出記録がないレイアウトは完成イメージとして提示しない
