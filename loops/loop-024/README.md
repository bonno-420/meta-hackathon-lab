## 問題の所在（統括の確認）

- これまでのレイアウトは固定テンプレート1本（page-layout の決め打ち構成）で、その形は統括が loop-020 で作ったモックに由来した。企画が決めていたのは「どの訴求・事実がどの枠に入るか」だけで、ページの構造そのものは企画から導かれていなかった。「企画から読み取って作った」は言い過ぎだった

## 仕組み化（src/lp-design.mjs）

- 構成パターンを候補として3つ置く: P-COND（条件先行、LIB-PAT-001 の順序）、P-WORK（仕事先行）、P-LIFE（生活適合先行）
- 導出は決定的: 企画の訴求（第一確認の事実を持つか／仕事そのものか／生活適合か）と画像指定の信号を数え、最も強い読み手関心のパターンを選ぶ。スコア・信号・理由は設計記録（lp-design.json と layout 記録）に残り、監査できる
- ページ生成（見本）と組み立て（完成LP）は同じ設計記録に従う。パレットもパターンに紐づくトークンとして記録される（市場の裏付けはない候補のまま、と記録に明記）
- ゲート追加: 設計の導出記録がないレイアウトは完成イメージとして提示しない

### runE2g 企画差し戻しと fixture 修正（2026-11-04）

- runE2g は企画レビュー不合格で停止: 判断順序の指摘（firstCheck は workHours と
  salaryHourly なのに給与の訴求 A3 が4番目に埋もれている）。同じ企画は runE2f で
  合格しており、単独審査のばらつきでもあるが、指摘の実質（給与を4番目に置かない）
  は編集判断として妥当なので fixture を修正した: 訴求順 A1（仕事そのもの）→
  A4（平日・時間）→ A3（時給）→ A2（契約）→ A5（未経験・研修）。テスト用 fixture の
  修正であり、本人の承認行為ではない（テストループの指示に基づく）
- あわせて runE2g の初回実行で事実照合が止まった原因を修正した: 抽出候補の
  未記載項目の sourceLine が空文字で返り、固定側の null と不一致になった。
  空文字は「参照なし」のモデルの書き方として、照合と比較の両方で null に
  正規化する（extract-and-check / run-demo）

### runE2g–runE2j: 本人の仕様（見出し分離・画像設計・募集要項・訴求転換）の実装と検証（2026-11-04）
