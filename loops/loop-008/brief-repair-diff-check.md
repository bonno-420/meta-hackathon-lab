## 判断が分かれる項目

### §6 生成（正常系）行と、テストと実生成の分離

- 修復版 §6 の正常系行は「承認済みペアで実生成」をテスト設計の表に置いている。実施では、テストファイル内の生成はスタブ化し（実 API を呼ばない）、実生成はテストと分けて1回だけ実行して `generation-run.json` と生成物で検証可能にした
- 検証の意図（生成物が得られ、全文化が根拠を満たすことを確認できること）は、実生成1回＋根拠検査 pass＋実行内訳の記録で満たされていると判断する。一方で、テストファイル単体では実生成のケースを再現できない形であり、「テストとして残す」という §6 の建て付けとの字義どおりの一致ではない
- この分離は工程1・工程2のテストが API を呼ばない再現可能な形だったことと整合させる判断であり、run-record に理由が記録されている。修復版 §6 には「生成系の検証の置き方は整合で判断し、判断と理由を run-record に残すこと」と明記して、この実施形態を追認できる形にした。最終的な評価は監理ラインの監査に委ねる

### 生成物 JSON へのヘッダ追加

- 生成物は、ブリーフ作業1の提案形式（文ごとの本文・factKeys・sourceLines）に、入力の組を特定するヘッダ（kind・version・promptVersion・model・input）を加えた形になっている。文単位の形式自体は提案どおりであり、ヘッダは工程4が入力の組を特定する助けになる。妥当性は §9 のとおり監査で見てもらう点として残す

### 未記載項目に触れなかったこと

## 満たさない項目

### §6 生成（根拠検査）行の一部: 検出テストのカバレッジ不足

- `checkGrounding` は実装上、実在しない key（unknown factKey）と実在しない行 ID（unknown sourceLine）の検出を持つ（`src/generate.mjs`）。しかし `check-verification.json` の生成系7件には、この2種の検出を対象にしたテストケースがない。検証されているのは、忠実な出力への合格、未記載の断定の検出、捏造した金額の検出までである
- 根拠を持たない文（factKeys・sourceLines が空の文）の検出についても、同様に専用の検証記録がない
- **追加作業の要否**: §9 の完了条件（テストがすべて pass し記録があること）自体は現状でも満たすため、工程3の完了を妨げるものではない。ただし §6 の根拠検査行の期待に完全に対応させるには、次の補強を推奨する
  - 内容: 実在しない key を引く文、実在しない行 ID を引く文、根拠を持たない文の3ケースを `src/generate.test.mjs` に追加し、`check-verification.json` を再生成する。API は呼ばないため実費は発生しない
  - 実施時期: 監理ラインの監査で指摘された場合、または工程4（再検証）の着手前。本書の作成時点では実施していない
