## 変更内容（F1–F10）

- F1 文章投入口: `src/pin-posting.mjs`（新規）が求人文を原本形式に固定。`src/extract-and-check.mjs` は `--original/--input-id/--input-version` で対象を引数化（既定は FICT-J01 で従来どおり。E02 は FICT-J01 専用の評価ケースとして、その入力でのみ実行）。統合実行は投入モードで原本・FACT候補・マニフェストを既存形式で書き、承認で止まる。承認は作らない
- F2 企画入力: `src/planning.mjs`（新規）。企画ファイル（対象・訴求・言わないこと・画像対応表・一次確認キー）を検証しハッシュで記録。無ければ承認後に「企画待ち」のチェックポイント停止。生成の意図層は `generate-persona.mjs` の固定 INTENT から企画ファイル由来（`intentFromPlanning`）へ。`src/generate-planning.mjs`（新規）がその実行器
- F3 1枚画: 対応表（全要素に企画項目か FACT の根拠を必須化。未記載項目を根拠にした要素は例外で拒否）→ 禁止モチーフ（企画の「言わないこと」の語＋常設禁止: 現金・収入表現、具体的な時刻、未記載の寮がある場合の住居表現）でプロンプトを決定的に検査 → 生成 → 提示記録（loop-020 チェックリストの確認欄つき）→ チェックポイント停止。再開は確認記録（ファイル・ハッシュ・確認者・日時）と実ファイルのハッシュ一致が条件
- F4 実画像: `decideImagePlanFromSpecs` が対応表から計画を作り、`generate-images.mjs` の `--plan-file` モードで実行。固定テンプレートは固定デモ経路にのみ残り、パイプライン経路では使わない
- F5 組み立て: ヒーローに確認済み1枚画＋一次確認 FACT 値のチップ（FACT の値そのまま）。文は従来どおり各1回、検証側の家具は入れない
- F6 C5: `src/pagecheck.mjs`（新規）が loop-016 の決定的チェック（重複文・検証側定型文・記録ラベル・見出しスコープ）を移植。辞書は `src/dicts/` に版管理（13/13/4件、loop16-dicts-2026-11-02）。`checkCompletion` に C5 を追加（runner 側）。`verify.mjs` は無改変（git 上で未変更を確認）
- F7 チェックポイントと提示記録: 開始前に full（企画・1枚画・文章・組みあがり）/ light（1枚画・組みあがり）を選択し記録。各チェックポイントで R2 形式の提示記録（提示物・保留・判定欄）を書き、状態ファイルで再開可能にする
- F8 リトライと保留（R1表）: 抽出・照合・比較・承認は再試行しない。文章生成・1枚画・実画像は上限3回まで再試行し、尽きたら保留として記録する。画像の保留時は期待ファイル一覧で完成判定するため、保留が完成に化けない
- F9 根拠検査の一般化: `checkGrounding` の数値表を固定値（1,500/10,000/60/8）から、引用した FACT の normalized からの導出に変更
- F10 学習入力: フィードバックメモをファイル入力として受け取り（ハッシュ記録）、意図層の拘束入力として生成に渡す。メモの編纂が人間/統括の作業であることは生成器の記録に明記
