# loop-029 — チェックポイントを「流れの中の質問」にする（make-lp の対話化）

2026-11-04 夜。実施: 統括（本人の指示による）。対象は入口ラッパー `make-lp.mjs` のみ。`src/run-demo.mjs`・各ゲート・`src/verify.mjs` は無変更。

## 発端（実測した事実）

- 同日、架空求人 Sorano Wheel の LP がパイプライン外で手組みされた件を受け、入口を `make-lp.mjs` に一本化した（7e4d590）。
- その後、本人の PC のラインが同求人を入口経由で走らせ、承認チェックポイントで正しく停止した。ところが続きの手順が「承認ファイル（sha256 入り JSON）を人間が自分で作れ」という提示であり、ラインは「承認ファイルは自分では書かない」と線を引いた。
- 本人の訂正が3段で確定した:
  1. 「これ質問形式じゃないんだ」— 承認は質問に答える形であるべきで、JSON を手で書く宿題ではない
  2. 「横からそんな操作しないといけないならだめだよ」— 別コマンドや手続きを横から差し込む形も違う
  3. 「そんなん細かくいろいろやらないと動かないのはダメ」— 細かい操作の積み重ねでしか動かないものは製品ではない
- あわせて本人の指定: 「生成物はプレビュー表示、何択かの選択性の質問で進めるイメージ」

## 設計（本人の言葉の範囲で）

- 本人の操作は `node make-lp.mjs <求人テキスト>` の1回だけ。
- チェックポイント（事実の承認・企画・1枚画・文章・組み上がり）に来たら、make-lp がその場で生成物のプレビューページをブラウザに開き、選択式の質問（ボタン）と任意のメモ欄を出す。ターミナル側でも同じ質問に番号で答えられる（どちらか先に答えた方を採用）。
- 判断は人間、記録の作成（ハッシュ計算・ファイル書き込み）は道具の事務。承認記録の basis に回答経路（preview / terminal）を残す。
- 名前（承認者・確認者）は初回だけ聞き、ローカルの `.loopwright-operator.json`（Git 対象外）に保持。以後は既定値として提示する。
- 「止める」を選ぶことは正当な結果であり、その場合はいかなる記録も作らない（捏造にならない）。
- 非対話実行（エージェント・スクリプト）では従来どおり: 1回走らせて停止を結果として報告し、記録は一切作らない。ゲート停止（矛盾・検証不合格）は対話モードでも質問にせず、結果として報告する。

## 実装

- `make-lp.mjs` を改修: 駆動ループ（停止→質問→記録→自動再開、最大12往復）、localhost プレビューサーバ（生成物の表示＋選択式質問、ファイル配信はリポジトリ内に限定）、承認記録・1枚画確認記録・提示 judgement の作成、操作者名の保持。
- `AGENTS.md` の入口節に、この対話形が「エージェントが記録を作らない」原則の例外ではなく人間の回答の記録である旨を明記。`.opencode/skills/loopwright/SKILL.md` にも1行追加。`.gitignore` に `.loopwright-operator.json` を追加。

## 検証（実走、FICT-E03 流用、runs/FICT-E03-FLOWTEST）

- 抽出→承認停止: プレビューページから「承認して進める」を回答（Web 経路）。make-lp が承認記録 `FICT-E03-FLOWTEST-approval-1` を作成し自動再開。リポジトリ自身の `checkGenerationInput` で照合: **ok: true**（original / facts 両ハッシュ一致）。
- 再開後: 企画ドラフト→企画レビュー pass→1枚画生成→1枚画チェックポイントで停止。プレビューと質問が開いたことをログで確認。
- ターミナル経路: 同 run を `--resume` し、1枚画の質問にターミナルで「2) 止める」を回答。記録は作られず、停止が結果として報告されて終了（捏造なし）。
- 未検証の範囲: 文章チェックポイントと組み上がり（最終 LP）プレビューの質問は、同じ仕組みで実装したが、本検証では実走で到達していない。到達には完成までの実走が要る。
